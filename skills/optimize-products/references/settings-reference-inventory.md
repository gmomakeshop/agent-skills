# 在庫

在庫は仕入に使った現金が商品の形に変わったもの。設定の目的は「売れるのに在庫がなくて売り逃す（欠品）」と「売れないのに在庫を抱え続ける（過剰在庫）」の両方をなくすことにある。在庫数・注文上限数・注文下限数・再入荷お知らせの設定と、発注の判断ルールをセットで整える。

## 在庫数の設定

### 1. 在庫が有限な商品は実数を入力する

ECでは在庫を目視で確認できない。「無制限」のまま運用すると、実在庫が尽きても注文を受け続け、出荷できない注文・キャンセル対応・クレームが発生する。実数を入力しておけば在庫が尽きた時点で自動的に売り切れになる。「無制限」はダウンロード商品や受注生産など、実在庫が尽きない商品に限る。

在庫アラート機能があれば、通知の基準値を発注点（4）に合わせて設定する。

### 2. 色・サイズのある商品はバリエーション単位で登録する

商品単位の合計だけで管理すると、「合計では在庫があるのに、売れ筋のMサイズだけ欠品している」状態が見えない。売上は一部の人気バリエーションに集中するため、合計在庫の管理では主力の売り逃しを発見できない。在庫はSKU（色×サイズ）単位で登録し、販売実績・発注判断もSKU単位で行う。

### 3. 登録在庫と実在庫のズレをなくす

ここがずれていると、発注判断も売り切れ制御もすべて狂う。ズレの典型原因は、入出庫の反映漏れ、返品・破損の未処理、複数チャネル併売による売り越しの3つ。

- 出荷・入荷・返品・破損のたびに在庫数へ反映する
- 月1回など頻度を決めて実在庫を数え、登録在庫と突き合わせる
- 複数チャネル併売の商品は、在庫連携に反映のタイムラグがあるため、実在庫から予備を差し引いた数を各チャネルに登録する（例：実在庫20個 → 各チャネルに18個）

## 発注の判断

### 4. 発注点を決めて、下回ったら機械的に発注する

「残りわずかになってから発注」では、入荷までのリードタイム中に在庫が尽きる。

```
発注点 = 1日の平均販売数 × リードタイム（日数） + 安全在庫数
```

例）日販5個・リードタイム7日・安全在庫10個 → 発注点45個。在庫が45個を下回ったら発注する。在庫10個で発注すると、入荷までの7日間で35個売れるため入荷前に尽きる。

### 5. 安全在庫は計算式で決める

安全在庫は需要のブレと入荷遅延を吸収する予備在庫。多すぎれば過剰在庫、少なすぎれば欠品になる。「なんとなく多めに」ではなく、過去の販売数のばらつき（標準偏差）と許容する欠品率から計算する。標準偏差は表計算ソフトのSTDEV関数で日別販売数から求められる。

```
安全在庫 = 安全係数 × 販売数の標準偏差 × √（リードタイム + 発注間隔）
安全係数（正規分布のz値）：欠品許容率5% → 1.65 / 10% → 1.29 / 1% → 2.33
```

例）標準偏差3個・リードタイム7日・発注間隔8日・欠品許容率5% → 1.65 × 3 × √15 ≒ 19個。

全商品一律の安全在庫は、安定した商品では過剰、ブレの大きい商品では欠品を招く。季節商品はデータを季節ごとに分けて計算する。

### 6. 発注量は過去実績にもとづく需要予測で決める

勘で決めると欠品か過剰在庫のどちらかに振れる。季節性をとらえるには最低1〜2年分の販売実績が必要だが、専門的な統計手法は要らない。

1. 予測したい月の過去2年の同月販売数と、直近2〜3か月の販売数を並べる
2. セール期間の急増や品切れ期間の機会損失など、イレギュラーな数字は理由を記録して補正する
3. 季節性と直近の伸び率から翌月の販売数を推算する
4. 頻度を決めて、予測と実績の差を確認しながら更新する

### 7. 需要が読めない商品は試験的に小さく発注する

新商品で予測値どおりの数量を一度に発注するのは在庫リスクが大きい。まず予測の一部（半分など）を発注し、実際の売れ行きを確認してから残りを調整する。大量発注割引は魅力的だが、必要数を超えた抱え込みは保管コストと売れ残りリスクで割引分を食いつぶす。

## 在庫の評価

### 8. 在庫回転率と交差比率で投資効率を評価する

「売れている商品」と「儲かっている商品」は別物で、売上だけを見ると判断を誤る。

```
在庫回転率（回/年） = 年間売上原価 ÷ 平均在庫金額
　平均在庫金額 = （期首在庫金額 + 期末在庫金額） ÷ 2
交差比率（%） = 在庫回転率 × 粗利益率（%）
```

交差比率は、回転は遅いが粗利が厚い商品（厚利少売）と、粗利は薄いが回転が速い商品（薄利多売）を同じ土俵で比較できる。絶対的な合格ラインを決めるのではなく、自店の商品どうしを並べて相対的に判断する。

例）商品A：回転8回 × 粗利20% = 160%／商品B：回転3.5回 × 粗利60% = 210%／商品C：回転2回 × 粗利30% = 60%。売上額がAで最大でも資金効率はBが最良、Cは値引き消化・仕入縮小・取り扱い終了の検討対象。

### 9. 指標で定期点検し、管理の手間を配分する

```
消化率（%）  = 販売数 ÷（販売数 + 残在庫数）× 100
在庫残り日数 = 残在庫数 ÷ 1日の平均販売数
```

- 在庫残り日数がリードタイムを下回りそう → 欠品予備軍。すぐ発注する
- 消化率が低く在庫残り日数が長い → 過剰在庫。値引き・露出強化で消化を図る

あわせて売上貢献度でABCの3グループに分け、管理の濃淡をつける。A（売上上位）は発注点・需要予測を整備して欠品させない。B（中位）は発注点のみ設定し定期点検。C（下位）は在庫を最小限にし、売り切り・整理を検討する。

## 見せ方と販売単位

### 10. 残り在庫の見せ方で「今買う理由」をつくる

人は手に入りにくいものほど価値を感じる（希少性）。在庫が潤沢な商品の数字をそのまま見せると「いつでも買える」と後回しにされるため、残り在庫が一定数（5個前後が目安）を下回ったときだけ「残りわずか」と見せる設計にする。在庫表示を記号に切り替える機能があれば、同じ考え方で基準値を設定する。

### 11. 在庫切れの商品ページは消さずに「再入荷待ち」にする

再入荷予定のある商品のページを削除・非公開にすると、検索エンジンの評価と検索流入がリセットされ、再入荷時にゼロから積み直しになる。ページは公開したまま品切れ表示にし、再入荷お知らせを受け付ければ、購入意向のある顧客の連絡先が集まる。登録数は「あといくつ仕入れれば売れるか」を示す需要データにもなる。

一方、品切れ商品が一覧の前方に並び続けると買える商品を探す顧客の邪魔になるため、一覧では後方に下げる。廃番で再販しない商品だけは、後継商品のページへ転送するか、類似商品への案内を載せる。

### 12. 入荷を待たせる商品は予約販売・受注生産に切り替える

人気で生産が追いつかない商品や、需要が読めず在庫リスクの大きい商品は、「在庫を持ってから売る」のをやめて「注文を受けてから仕入れる・作る」方式が選べる。予約販売は欠品期間の売上を取り逃さず、注文数がそのまま生産・仕入数量の根拠になる。代わりに顧客を待たせるため、発送時期の明示が必須。

| 商品の状況 | 判断 |
|---|---|
| 欠品期間が次回入荷まで2週間を超える人気商品 | 予約販売で注文を確保する |
| 需要が読めない高単価・高リスク商品 | 受注生産・受注仕入で在庫リスクを抑える |
| 常に在庫があり即納が競争力の消耗品 | 切り替えない（在庫販売を維持） |

### 13. 注文上限数と注文下限数で販売単位と公平性を設計する

在庫が限られた人気商品・セール品は注文上限数を設けて買い占めを防ぐ。ケース売り・セット売りなど一定数量でないと採算が合わない商品は注文下限数で販売単位を守る。注文下限数は注文画面の数量の初期値にもなるため、まとめ買い前提の商品では入力の手間も減る。

例）在庫50個の限定商品に注文上限数3個 → 最低17人に行き渡る。24本ケース売りに注文下限数24本 → 1本注文による採算割れを防ぐ。

## 症状別の打ち手

| 症状 | 状態 | 打ち手 |
|---|---|---|
| 出荷できない注文が発生 | 在庫数が「無制限」のまま | 実数を入力する（1） |
| 売れ筋がしょっちゅう在庫切れ | 発注が遅くリードタイム中に尽きる | 発注点を決めて機械的に発注する（4） |
| 発注が後手に回る | 在庫確認が目視頼み | アラートの基準値を発注点に合わせる（1、4） |
| 需要急増・入荷遅延で欠品 | 安全在庫の見込みが足りない | 計算式で安全在庫を積み増す（5） |
| 人気の色・サイズだけ欠品 | 商品合計でしか見ていない | SKU単位で登録し、SKU単位で発注する（2） |
| 在庫切れページを放置・削除 | 流入と購入意向を取りこぼす | ページ公開のまま再入荷お知らせを受け付け、一覧では後方に下げる（11） |
| 再入荷お知らせを活かせない | 需要データとして使っていない | 登録数を再入荷数量の判断材料にし、入荷後すぐ通知する。商品が非表示・掲載期間外だと通知が届かないため公開状態を先に確認する |
| 欠品期間が長引く | 在庫販売のままで売上ゼロ | 予約販売に切り替えて注文を先に確保する（12） |
| 季節商品の発注量が読めない | 直近だけで判断している | 過去2年の同時期実績から季節性を読み取る（6） |
| 新商品の初回発注量が決まらない | 実績ゼロ | 試験的に小さく発注し、初動を見て調整する（7） |
| 売れ残り在庫を処分したい | 保管コストと資金を圧迫 | 消化率・在庫残り日数・交差比率で対象を特定し、値引き設計へ（8、9、`references/settings-reference-pricing.md`） |
| どの在庫から手を付けるか分からない | 全商品を同じ濃度で管理 | ABCに分け、上位から整備する（9） |
| 買い占められる | 数量制限がない | 注文上限数を設ける（13） |
| 単品注文で赤字になる | 販売単位が守られていない | 注文下限数を設ける（13） |
| 在庫の動きが鈍い | 1個ずつしか買われない | まとめ買い特典を設定する（`references/settings-reference-pricing.md`） |
| 登録在庫と実在庫が合わない | 反映漏れか売り越し | 棚卸しで合わせ、入出庫のたびに反映するルールと定例棚卸しを設ける（3） |
| 購入を後回しにされる | 「いつでも買える」と思われている | 一定数を下回った商品だけ「残りわずか」と表示する（10） |
