# SEO

設定対象はページタイトルとメタディスクリプションの2つ。商品ごとの個別設定と、全商品に同じテンプレート文を適用する一括設定がある。サイト内検索でのヒットは`references/settings-reference-search-keywords.md`を参照。

SEO改善の提案は、「販売数が少ないのに利益率が高い＝露出が足りない」「売上が下落しており単価は横ばい＝流入減が主因」など、データから読み取れる問題を起点に組み立てる。設定変更が順位に反映されるまでには数か月かかるため、即効性を求める場面では他の施策と組み合わせる。

## ベストプラクティス

### 1. 一括設定を安全網にして、売れ筋から個別設定で上書きする

個別設定がない商品には一括設定のテンプレート文が反映される。一括設定では「商品名」「カテゴリー名」「ショップ名」の変数が使え、各ページの情報に自動で置き換わるため、設定漏れをなくす安全網になる。ただし商品固有の検索クエリには最適化できない。

1. 一括設定に変数入りのテンプレートを登録し、未設定の商品をなくす
2. 売上・アクセス上位の商品から順に個別設定で上書きする（対象が多ければCSVの一括登録）
3. 新商品の登録フローに個別設定まで書き切る運用を組み込む

### 2. ページタイトルは主要キーワードを冒頭に、全角32文字以内

入力上限は全角32文字で、検索結果に表示されるタイトルもそれを超えた分は省略される。検索エンジンもユーザーも先頭の語を重視するため、最も重要なキーワードを前半に置く。

構成：`[主要キーワード] + [属性・特徴] + [| ブランド名]`

- 悪い例：`職人が丁寧に仕上げた横向き寝にも対応するやわらかめ低反発まくら ホワイト | ショップ名`
- 良い例：`低反発枕 横向き寝対応 高さ調整可 | ブランド名`

設定したタイトルは検索エンジンに書き換えられることがある。同じ語の繰り返しや極端に長い・短いタイトルは書き換えの対象になりやすい。

### 3. キーワードは「候補出し → 検索数 → 上位ページ」の3手順で決める

感覚で選んだキーワードは、誰も検索していないか、強すぎる競合が独占しているかのどちらかになりやすい。

1. **候補出し**：検索窓に商品ジャンル名を入れてサジェストを集める。大手モールのサジェストは購入目的の語が多く優先度が高い
2. **検索数の確認**：キーワードプランナー等で月間検索ボリュームを確認する。検索数が中程度の語が個店でも上位を狙いやすい
3. **上位ページの確認**：候補キーワードで実際に検索し、上位10件の顔ぶれを見る。大手モール・有名ブランドばかりなら別の候補に切り替える

### 4. 購買意欲が表れたロングテールを狙う

1語のビッグキーワードは検索数こそ多いが、情報収集目的が混ざるうえ大手と競合する。複数語のロングテールは競合が少なく、ニーズが具体的なぶん購入に近い。キーワードは「検索ボリューム」「競合の強さ」「商品との関連性」「検索意図」の4つで評価する。

- 悪い例：`カーテン`
- 良い例：`遮光カーテン 1級 幅100cm 丈200cm`

### 5. メタディスクリプションは文頭に要点を置く

入力上限は全角124文字。検索結果に表示されるのはPCで約120文字、スマートフォンではさらに短く、それ以降は切れる。重要なキーワードとメッセージは文頭60〜80文字に収め、「ベネフィット訴求 → キーワードの自然な挿入 → 行動喚起」の順で構成する。

順位に直接影響する要素ではないが、ユーザーの検索語と一致した語は検索結果で太字表示されるため、狙うキーワードを含めることがクリック率に効く。限定数量・期間限定・メディア掲載などの固有情報があれば入れる。

### 6. 商品ごとに固有のタイトル・ディスクリプションを書く

複数ページで同じ文を使い回すと重複コンテンツと判定され、どれか1ページしか評価されない。定型文の一部だけを差し替えたタイトルは書き換えられやすい。メーカー提供の説明文をそのまま使うのも、同じ文面を載せる他店すべてと重複する。類似商品でも色・容量・用途の違いを反映した固有の文を書く。

### 7. キーワードは詰め込まず、自然な文の中に分散させる

不自然な繰り返しや羅列は低品質・スパムと判定されるリスクがあり、ユーザーにも読まれない。同じキーワードはタイトルに1回・説明文に1〜2回程度に抑え、言い換えや関連語（遮光カーテンなら「ドレープカーテン」「遮熱」）を織り交ぜる。

### 8. ページ本文のテキストも充実させる

検索エンジンはページ全体のテキストを読んで内容を評価するため、本文が薄いと正しく評価されない。メタディスクリプションが本文と食い違っていると、本文から抜粋した別の文に差し替えられることもある。商品名・素材・寸法・使い方・利用シーンをテキストで記載する（`references/settings-reference-description.md`）。

### 9. 画像のalt属性とファイル名を具体的にする

検索エンジンは画像の中身を直接は理解できず、alt属性・ファイル名・周辺テキストから推測する。altには「何が写っているか」を商品名・色・素材・アングルで書き、ファイル名もアップロード前に内容を表す語に変える。

- 悪い例：`alt=""` / `IMG_1234.jpg`
- 良い例：`alt="真鍮 ペンダントライト 点灯時"` / `brass-pendant-light-on.jpg`

### 10. 構造化データで価格・在庫・レビューを表示させる

商品の構造化データ（JSON-LD推奨）があると、検索結果に価格・在庫状況・レビューの星評価が表示されるリッチリザルトの対象になる。多くのカートシステムは商品登録の情報から基本的な構造化データを自動出力するため、まず商品情報を管理画面に正確に登録することが第一歩。リッチリザルトテストで検証し、エラーがあれば不足項目を補完する。実際の価格・在庫と食い違う内容を記載すると、ガイドライン違反と判断されるおそれがある。

### 11. Search Consoleで順位とクリック率を定点観測する

感覚で判断すると場当たり的な変更を繰り返すことになる。

1. 検索パフォーマンスレポートで「平均CTR」「平均掲載順位」を有効にする
2. ページフィルタで商品ページを指定し、どの検索語で何位かを確認する
3. 掲載順位は高いのにCTRが低いページを抽出する
4. タイトル・ディスクリプションをリライトし、変更前の数値を記録して28日後に比較する

「順位を上げる施策」と「クリック率を上げる施策」を取り違えない。

### 12. AI検索に引用されることを意識して事実情報を明確に書く

AI要約や対話型AIの回答に引用されるには、参照しやすい正確で構造的な事実情報が要る。SEOで評価されているページはAIにも参照されやすいため、通常のSEOを土台に上乗せする。

1. スペック表記を統一する（「500ml」「0.5L」などの混在をなくす）
2. 商品説明の冒頭1〜2文で「何がどう良い商品か」の結論を述べる
3. 購入前によくある質問と回答を本文に載せる

### 13. noindexとcanonicalで検索結果に載せるページを管理する

情報が薄いページや重複ページばかりがインデックスされると、サイト全体の評価に逆効果になる。検索結果に出す必要のないページは`noindex`で除外し、同じ商品に複数URLがある場合は`canonical`で1つに正規化する。

## 症状別の打ち手

| 症状 | 状態 | 打ち手 |
|---|---|---|
| 一括設定のまま放置 | 売れ筋まで汎用文 | 流入・売上上位から個別設定で上書きする（1） |
| タイトルが途中で切れる | 長すぎるか重要語が後半 | 全角32文字以内に収め、主要キーワードを冒頭へ（2） |
| 説明文が意図しない文になる | メタディスクリプション未設定 | ベネフィット→行動喚起の文を個別に登録する（5） |
| 設定と違う文が表示される | 検索エンジンに書き換えられている | 同じ語の繰り返し・定型文の使い回し・本文との不一致を解消する（2、6） |
| 類似商品で使い回している | 重複コンテンツ判定 | 色・容量・特徴の違いを反映して固有化する（6） |
| ビッグキーワードで順位が付かない | 競合が強すぎる | 3手順でロングテールに切り替える（3、4） |
| 表示されるがクリックされない | クリックする理由がない | 順位のわりにCTRが低いページを抽出し、数字や固有のベネフィットを入れてリライトする（5、11） |
| キーワードの羅列になっている | スパム判定のリスク | 自然な文に書き直す（7） |
| メーカー説明文のまま | 他店と重複 | 自店の視点で書き直す（`references/settings-reference-description.md`） |
| 検索結果に価格や星が出ない | 商品情報の登録漏れ | 商品情報を正確に登録し、リッチリザルトテストで検証する（10） |
| 画像検索から流入がない | altが空・ファイル名が連番 | altとファイル名を具体化する（9） |
| AI要約に出てこない | 事実情報が薄い | スペック統一・結論先出し・FAQ追加（12） |
| 同じ商品が複数URLで公開 | 評価が分散している | canonicalで正規URLを1つ指定する（13） |
| 出したくないページが出ている | テスト用・情報の薄いページ | noindexで除外する（13） |
| 変えたのに効果が出ない | 再評価に時間がかかる | 変更日と変更前の数値を記録し、月1回定点観測する。3〜6か月変化がなければ本文の充実へ移す（11） |
| サイト内検索と混同している | 設定する項目が違う | 外部検索エンジン向けはこのリファレンス、ショップ内の検索窓は`references/settings-reference-search-keywords.md` |
