# 検索語

検索窓を使う顧客は買うものを決めて探しているため、購入に近い。ヒットさせたい言葉を検索対象の項目にテキストとして置き、表記ゆれと用途語まで拾えるようにする。

## 検索の仕様

設定を決める前提として、サイト内検索の挙動を押さえる。

| 項目 | 挙動 |
|---|---|
| 検索対象 | 商品名・検索キーワード・独自商品コード・メインの商品説明文の4項目のみ。画像内の文字やスペック表の画像はヒットしない |
| 検索キーワードの上限 | 全角半角を問わず100文字。部分一致のため、スペース区切りで列挙すれば1語ずつヒットする |
| 複数語検索 | AND検索。かつ、すべての語が同じ1つの項目内に含まれている場合だけヒットする |
| 表記ゆれ | 自動補正されない。ひらがなで登録した語はカタカナ検索にヒットしない |
| 並び順 | 商品の登録・修正日時が新しい順 |
| カテゴリー | 未登録の商品は絞り込みで消える。非表示カテゴリーにのみ属する商品はキーワード検索にも出ない |

## ベストプラクティス

### 1. 検索対象の4項目にキーワードを置く

ヒットさせたい言葉は必ず4項目のいずれかにテキストとして置く。画像内の文字で訴求しても検索されない。

- 悪い例：商品名`超音波式アロマディフューザー` ＋ 画像内の文字だけで「加湿器としても使えます」
- 良い例：検索語に`加湿器 卓上 寝室 オフィス 静音`を登録

### 2. 100文字の枠を関連語で計画的に使い切る

100文字は1語5文字として約15〜18語ぶんの枠。思いついた語を数個入れて終わりにせず、「言い換え」「表記ゆれ」「用途・シーン」「ターゲット」の4観点で洗い出し、優先度の高い語から使い切る。

例）`まな板 まないた カッティングボード 抗菌 食洗機対応 一人暮らし 新生活 キッチン 母の日 引っ越し祝い`

### 3. 表記ゆれは全パターン登録する

「まな板・まないた・カッティングボード」のように、顧客が入力しうる表記をすべて並べる。見つからなかった顧客は黙って競合ショップへ移る。

### 4. 組み合わせ検索される語は同じ項目の中に揃える

商品名に「ヨガマット」、検索キーワードに「厚手」と分かれていると、「ヨガマット 厚手」の2語検索にヒットしない。一緒に検索されそうな語は同じ項目内に揃えて置く。

- 悪い例：商品名`ヨガマット 10mm` ／ 検索語`厚手`
- 良い例：商品名`ヨガマット 厚手 10mm` ／ 検索語`ヨガマット 厚手 トレーニングマット ストレッチ 筋トレ 滑り止め`

### 5. 商品名にすでにある語を検索語に重複登録しない

商品名自体が検索対象のため、同じ語を入れても効果はなく100文字の枠を無駄にする。検索キーワードには商品名に**ない**語（言い換え・用途・悩み・略称）だけを登録する。ただし組み合わせ検索を狙う語（4）は例外。

### 6. 説明文に無関係なキーワードを詰め込まない

メインの商品説明文は検索対象のため、関係の薄い語を羅列するとその語の検索にまで商品がヒットする。「探していたものと違う」結果が並ぶ検索は顧客の信頼を下げ、ショップ全体の検索体験を壊す。説明文は顧客に読ませる文章として書き（`references/settings-reference-description.md`）、検索用の語は実態に合うものだけを検索キーワードに分離する。

### 7. 候補はサジェスト・モール・キーワードツールで集める

顧客が実際に入力する言葉は、頭の中で考えるだけでは網羅できない。

1. 検索エンジンの検索窓に商品ジャンル名を入れてサジェストを控える
2. 大手モールの検索窓で同じ語を入力し、検索候補と上位商品の商品名に使われている語を控える
3. サジェスト取得ツール・キーワードプランナーで関連語と需要の有無を確認する

集めた語から、自店の商品の実態に合うものだけを採用する。

### 8. 検索ログと0件ヒットを月1回確認する

何が検索され、何が0件だったかが、検索語設定の最重要の改善材料になる。0件ヒットは「買う気のある顧客をその場で帰す」機会損失。アクセス解析ツールでサイト内検索クエリを計測できるよう設定し、月1回「検索回数の多い語」「0件だった語」を確認して、検索キーワードの追加・商品名の修正・品揃えの検討につなげる。

### 9. 検索結果一覧での見え方を整える

ヒットしても一覧で選ばれなければ意味がない。一覧に表示されるのは主に商品画像・商品名の前半・価格。商品名は前半20〜30文字に「何の商品か + 最大の特徴」を凝縮し（`references/settings-reference-product-name.md`）、メイン画像はサムネイルでも商品が判別できるものにする（`references/settings-reference-images.md`）。

### 10. 主力商品の情報を更新し続ける

検索結果は登録・修正日時が新しい順に並ぶため、長期間更新していない商品は下に沈む。検索した顧客の多くは1ページ目しか見ない。売りたい主力商品は説明文の改善・画像の差し替えなどを定期的に行い、上位に表示される状態を保つ。

### 11. カテゴリー・価格帯の絞り込みでも見つかるようにする

顧客はキーワードだけでなく絞り込みでも商品を探す。すべての商品を、顧客の探し方に合った表示中のカテゴリーに登録する。

### 12. 登録・変更したらテスト検索する

設定したつもりでも、ヒットするか・何番目に表示されるかは検索してみないと分からない。主要キーワード3〜5語と、想定される2語の組み合わせ1〜2パターンで自店を検索し、ヒットの有無・表示順・一覧での見え方を確認する。

### 13. 在庫切れ・販売終了の商品で検索結果を埋めない

上位が在庫切ればかりだと、顧客は「このショップには無い」と判断して離脱する。長期欠品の商品は非表示や再入荷お知らせ登録への切り替えを行い、検索結果を「いま買える商品」で保つ（`references/settings-reference-inventory.md`）。

## 症状別の打ち手

| 症状 | 状態 | 打ち手 |
|---|---|---|
| 主要キーワードで出てこない | 検索対象の4項目にその語がない | 最優先で追加する。商品名に入れると不自然な語は検索語へ逃がす（1） |
| 表記ゆれでヒットしない | 1つの表記しか登録していない | 想定される表記・略称をすべて列挙する（3） |
| 2語検索でヒットしない | 語が項目をまたいでいる | 組み合わせ検索されそうな語を同じ項目内に揃える（4） |
| 検索回数が多いのに0件 | 需要に応えられていない | 既存商品でカバーできる語は検索語へ追加。該当商品がなければ品揃えの検討材料にする（8） |
| 型番で探す顧客を逃す | 型番・規格が入っていない | 型番を商品名に含め、独自商品コードを型番に合わせて整備する（1） |
| 出ているがクリックされない | 一覧で競合に負けている | 商品名の前半とサムネイルを直す（9） |
| 下に埋もれている | 長期間更新していない | 商品情報を見直して鮮度を保つ（10） |
| 似た商品で選べない | 違いが分からない | 容量・色・用途など「違いが分かる語」を商品名に入れる |
| 在庫切れが上位を占める | 買える商品が見えない | 長期欠品は非表示・再入荷お知らせに切り替える（13） |
| 無関係な検索にヒットする | 説明文にキーワードを羅列している | 羅列を削除し、実態に合う語だけを検索語に残す（6） |
| 絞り込みで消える | カテゴリー未登録 | 表示中のカテゴリーに登録する。所属カテゴリーの表示状態も確認する（11） |
| 検索流入はあるが買われない | 検索語と商品の実態がズレている | 誇張・無関係語を削除 → 説明文・価格へ切り分ける |
| 季節需要を逃す | 検索される語が変わる | 需要期の前にサジェストで増える語を確認して追加し、需要期後に入れ替える |
| 新商品が見つからない | 登録時のチェックがない | 検索語の枠を活用 → 表示中カテゴリーに登録 → テスト検索、を登録フローに組み込む（12） |
